# Безопасность и аудит

## Границы доверия

Сайт статический, без аутентификации, пользовательских загрузок, базы, аналитики или персональных данных. Входные данные: URL/hash, элементы управления и HTTP-путь локального демонстрационного сервера. Текст выводится React без `dangerouslySetInnerHTML`; ключи глав фиксированы. Внешняя геометрия преобразована заранее, не загружается с чужого origin при посещении. Локальный сервер ограничивает пути каталогом `out/`; не размещайте в нём приватные файлы или симлинки на них. Для публичной публикации используйте статический хостинг с HTTPS, не этот демонстрационный сервер.

`vercel.json` содержит CSP, nosniff, frame deny, referrer policy и permissions policy. На ином хостинге заголовки нужно настроить отдельно. CSP разрешает inline-скрипты Next export и WASM Meshopt, но не сторонние origin. HSTS настраивает HTTPS-хостинг; на локальном HTTP его не включаем.

## Известное исключение зависимостей — 2026-10-15

`npm audit --omit=dev`: **0** известных уязвимостей. Полный `npm audit`: **5 high**, одна исходная уязвимость и четыре транзитивных эффекта:

`eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces`.

Advisory: https://github.com/advisories/GHSA-vfj7-8cjw-p6xm — stack-exhaustion DoS на глубоко вложенном glob-шаблоне, `braces <=3.0.3`. В установленной цепочке нет исправленной версии `braces`; предлагаемый npm автоматический «fix» понижает eslint-config-next до 14.2.35, несовместимого с принятым Next 16, поэтому `--force` не применён.

**Достижимость:** dev-only lint, обрабатывающий локальные исходники/шаблоны. Не входит в статический `out/` и не вызывается посетителем. Риск при lint недоверенного репозитория остаётся: запускайте его в ограниченной среде, не подставляйте недоверенные glob-шаблоны. Решение — временно оставить совместимый lint, не маскируя аудит overrides на несуществующий патч. Повторить проверку **до публичного релиза или 2026-10-22**, что наступит раньше. Полностью чистым аудит не объявляется.

Файл lock обязателен; используйте `npm ci`. Audit проверяет только известные advisories и не доказывает отсутствие supply-chain риска. Скрипты подготовки ресурсов не выполняются в обычной сборке. Ни ключей API, ни токенов для работы сайта не требуется.
